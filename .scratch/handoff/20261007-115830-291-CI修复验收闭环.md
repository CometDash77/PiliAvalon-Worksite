## 环境与陷阱（本会话实测，勿重踩）

- gh CLI 必须经 pwsh 工具通道执行：run_code 进程 env 为空，gh 报 "gh auth login"。gh 静默成功必须双通道验证（gh pr view --json + gh api）。
- **PowerShell 双引号内 \" 会拆参数**：gh --jq '.state + \" \" + .mergeCommit.oid' 这类表达式会让 jq 输出全空且无报错（本会话踩过，merge 后一度误判失败）。jq 表达式避免内嵌引号字符串，改用无 jq 纯文本或逗号分隔字段。
- run_code 代码字符串里写反斜杠 Windows 路径会报 "Legacy octal escape"——一律用正斜杠。
- tools.pwsh 返回 stdout 是 {text, truncated, spillPath} 对象：必须取 .stdout.text；把结果对象直接拼进 JSON 返回会得到 [object Object] 甚至 "program completion must be lossless JSON" 失败。
- CI 流程模板：PR 无 checks → gh workflow run ci.yml --ref <branch> dispatch（约 12 分钟）→ 绿后 gh pr merge N --merge → production push run（约 11 分钟）= exact-SHA 证据。watch 用后台 job：gh run watch <id> --repo ... --exit-status，job 完成有系统通知，勿轮询。
- 同一 worktree 永远只跑一个 flutter 命令（S3 会话教训，本会话已遵守）。
- merge 惯例：gh pr merge N --merge。动票前 deck_context，开工/完工 deck_issue_report。
- 本地 flutter 在 D:\flutter-sdk\flutter\bin\flutter.bat（issue #66 基线评论有记录）。
- 敏感信息：无（gh token 仅 keyring，未落任何文件）。
